# 사랑방(Sarangbang) — 핵심 기능 및 구현 설계서

버전 0.5 · 2026-11-16

## 1. 개요

개인 PC에서 가볍게 켜는 IRC형 채팅 시스템. 서버 프로그램과 윈도우 클라이언트 프로그램 두 가지로 구성한다.

핵심 제약

- 서버는 개인 PC다. 디스크가 작고, 항상 켜 둘 수 없다.
- 따라서 **파일·이미지는 서버 디스크에 절대 저장하지 않는다.** 서버는 글자 메시지와 "누가 어떤 파일을 보냈다"는 정보(이름·크기)만 보관한다.
- 서버가 꺼져 있는 동안은 채팅이 불가능하다. 대신 켜면 방·구성원·대화 기록이 그대로 복구된다.

## 3. 구조

```
[클라이언트 A] ──┐                    ┌── [클라이언트 B]
[클라이언트 C] ──┼── WebSocket ── [서버] ──┼── [클라이언트 D]
                 │      (개인 PC)       │
                 │   SQLite: 계정·방·글자 메시지
                 └── 파일 조각은 메모리로만 통과 (디스크 기록 없음)
```

- 서버: Node.js 22 + `ws`. DB는 Node 내장 SQLite(`node:sqlite`) — 별도 설치·컴파일 없음.
- 클라이언트: Electron(윈도우 설치형). 화면은 HTML/CSS/JS, 빌드 도구 없이 동작.
- 통신: WebSocket 한 개. 글자 프레임은 JSON, 바이너리 프레임은 파일 조각.

### 폴더 구성

```
   ├─ preload.js         화면 ↔ 메인 연결
   └─ renderer/          화면(index.html, app.js, style.css)
```

## 4. 파일 전송 설계 (서버 무저장)

1. 보낸 사람이 파일을 고르면, 클라이언트는 파일을 **자기 PC에 그대로 둔 채** 방에 "파일 메시지"(파일ID·이름·크기)만 올린다.
2. 받는 사람이 받기를 누르면 서버가 보낸 사람에게 요청을 전달한다.
3. 보낸 사람 클라이언트가 파일을 256KB 조각으로 읽어 보내고, 서버는 조각을 받는 즉시 받는 사람에게 넘긴다.
4. 받는 사람이 조각을 받았다고 응답해야 다음 조각을 보낸다(한 번에 한 조각). 그래서 서버 메모리에는 전송당 최대 한 조각만 머문다.
5. 받은 파일은 받는 사람 PC의 `다운로드\Sarangbang` 폴더에 저장된다.

이 방식의 대가

- **보낸 사람이 접속해 있어야 받을 수 있다.** 오프라인이면 "보낸 사람이 접속 중이 아님"으로 표시되고, 다시 접속하면 받을 수 있다.
- 보낸 사람이 원본 파일을 지우거나 옮기면 더 이상 받을 수 없다.
- 서버 경유일 때는 전송 속도가 서버 PC의 인터넷 속도에 묶인다. 그래서 아래의 직접 전송을 먼저 시도한다.

### 4.1 P2P 직접 전송 (0.2)

받기를 누르면 먼저 두 PC 사이의 직접 연결(WebRTC 데이터 채널)을 시도한다.

1. 받는 쪽이 `file.request`에 `p2p: true`를 붙여 요청한다.
2. 보낸 쪽이 연결 정보(SDP, ICE 후보)를 `file.signal`로 보내고, 서버는 이것을 상대에게 전달만 한다. **파일 내용은 서버를 지나가지 않는다.**
3. 연결되면 64KB 조각으로 직접 보낸다. 보낼 것이 4MB 넘게 밀리면 잠시 멈춘다.
4. 다 받으면 받는 쪽이 `file.done`을 보내 서버의 전송 기록을 정리한다.
5. **8초 안에 직접 연결이 안 되면** 보낸 쪽이 `fallback` 신호를 보내고 서버 경유(위 3~4번 방식)로 자동 전환한다. 사용자는 아무것도 하지 않아도 된다.

화면에는 받는 중에 "직접 전송" 또는 "서버 경유"가 표시된다.

알아둘 점

- 직접 연결은 서로의 IP 주소를 알게 된다. 아는 사람끼리 쓰는 용도라 허용했다. 같은 공유기 안에서 잘 연결되도록 내부 IP 숨김(mDNS)을 껐다.
- 서로 다른 공유기 뒤에 있으면 주소 확인용 공개 STUN 서버(`stun.l.google.com`)를 사용한다. 파일은 이 서버를 지나가지 않는다. 일부 회사망·통신사망에서는 직접 연결이 안 되며, 그때는 서버 경유로 전환된다.
- 직접 전송 도중에 연결이 끊기면 그 전송은 실패 처리되고, 받기를 다시 누르면 된다(이어받기는 없음).
- 구버전 클라이언트와 섞여 있어도 동작한다(구버전은 서버 경유로 보낸다).

## 5. 프로토콜 요약

모든 요청은 `{t: "종류", id: 번호, ...}` 형태이고, 서버는 같은 `id`로 `{t:"ok"}` 또는 `{t:"err"}`를 돌려준다.

| 종류 | 방향 | 내용 |
|------|------|------|
| `register` / `login` | C→S | 가입, 로그인(비밀번호 또는 토큰) |
| `room.create` / `room.list` / `room.join` / `room.leave` | C→S | 방 관리 |
| `room.invite` / `invite.accept` / `invite.decline` | C→S | 초대 |
| `msg.send` | C→S | 메시지(방 또는 1:1), `replyTo`, `file`, `rich`(서식) 포함 가능 |
| `history` | C→S | 지난 대화 조회 |
| `call` | C→S | 상대 호출(상대가 꺼져 있어도 알림 내역에 저장) |
| `notice.clear` | C→S | 알림 내역 지우기(하나 또는 전체) |
| `msg` / `invite` / `notice` / `presence` / `room.update` | S→C | 실시간 알림 (`notice` = 나를 호출함) |
| `file.request` → `file.offer` → `file.accept` → `file.go` → (바이너리) ↔ `file.ack` → `file.end` | 양방향 | 파일 중계(서버 경유) |
| `file.signal` ↔ `file.signal` → (두 PC 직접 전송) → `file.done` | 양방향 | P2P 직접 전송의 연결 정보 전달 |

바이너리 프레임: 앞 4바이트 = 전송 번호, 나머지 = 파일 조각.

## 6. 데이터 저장 (서버)

| 테이블 | 내용 |
|--------|------|
| users | 닉네임, 비밀번호 해시(scrypt) |
| sessions | 로그인 토큰 |
| rooms | 방 이름, 공개 여부, 방장 |
| members | 방 구성원 |
| invites | 대기 중인 초대 |
| notices | 호출 알림 내역(사용자당 최근 100건) |
| messages | 글자 메시지, 답글 대상, 파일 정보(이름·크기만) |

글자만 저장하므로 메시지 100만 건이 약 200~300MB 수준이다. `RETENTION_DAYS` 설정으로 오래된 메시지를 자동 삭제할 수 있다.

## 6.1 트레이와 알림 (0.3)

- **창 닫기 = 트레이로 숨기기.** 프로그램은 계속 실행되어 호출을 받는다. 완전히 끄려면 트레이 아이콘 우클릭 → 종료. 이미 실행 중일 때 다시 실행하면 기존 창이 열린다.
- **알림 팝업.** 주 창을 보고 있지 않을 때(트레이·최소화·다른 프로그램 사용 중) 호출이 오면 화면 우측 하단에서 팝업이 올라와 메시지 일부를 보여 주고, 5초 뒤 아래로 내려가 사라진다. 팝업을 누르면 창이 열리고 호출된 방으로 이동한다. 주 창을 보고 있을 때는 팝업 없이 알림 내역에만 쌓인다.
- **알림 내역.** 왼쪽 방 목록 맨 위에 표시된다. 항목을 누르면 그 방으로 이동해 해당 메시지를 강조하고, 그 항목은 내역에서 빠진다. '모두 지우기'로 한 번에 비울 수 있다.
- 알림 내역은 서버에 저장한다. 그래서 프로그램이나 PC가 꺼져 있던 동안 받은 호출도 다음 접속 때 내역에 나타난다.
- 호출 종류는 두 가지: 메시지 안의 `@닉네임`(메시지 내용이 표시됨), 구성원 목록의 🔔 버튼(메시지 없이 찾는 알림).

## 6.2 글자 서식과 코드 입력 (0.4)

입력란은 워드나 팀즈처럼 **보이는 대로 편집**하는 방식이다.

- 입력란 위 버튼 줄: 굵게(Ctrl+B) · 기울임(Ctrl+I) · 밑줄(Ctrl+U) · 취소선 · 배경색(노랑/초록/분홍/파랑, 없애기) · 크기(작게/크게/아주 크게, 다시 누르면 보통) · 서식 지우기.
- **Enter 전송, Shift+Enter 줄바꿈.** 한글 조합 중의 Enter는 전송하지 않는다.
- 붙여넣기는 글자만 받는다(다른 프로그램의 서식은 버림).
- **코드 블록(0.5):** '코드' 버튼을 누르면 커서 위치에 코드 블록이 들어간다. 글자를 선택하고 누르면 그 글자가 코드가 된다. 블록 앞뒤로 서식 글자를 자유롭게 쓸 수 있고, 블록을 여러 개 넣을 수도 있다. 모두 한 메시지로 전송된다.
- 블록 안에서는 Enter가 줄바꿈, Ctrl+Enter가 전송, Tab은 들여쓰기다. '코드 밖으로' 버튼이나 ↓ 키로 블록을 벗어나 글을 이어 쓴다. 빈 블록에서 Backspace를 누르면 블록이 지워진다.
- 커서가 블록 안에 있으면 도구 줄이 언어 선택으로 바뀐다. 언어는 자동 인식 또는 직접 선택(SQL, JSON, JavaScript, Python, Markdown, 일반 텍스트).
- 여러 줄 코드·쿼리를 붙여 넣으면 언어를 인식해 그 자리에 코드 블록으로 넣는다.
- 받은 코드는 언어 이름, 색 입힘, 복사 버튼이 있는 상자로 보인다.

저장과 안전

- 메시지를 HTML로 주고받지 않는다. 허용된 조각 목록(`rich`)으로만 보낸다: 글자 조각 `{ s, b, i, u, x, bg, sz }`, 코드 조각 `{ t: 'code', lang, text }`.
- 서버가 조각을 허용된 모양으로 다시 만들어 저장하고(모르는 속성·값은 버림), 클라이언트는 조각을 글자로만 화면에 넣는다. 그래서 메시지에 태그나 스크립트를 넣어도 실행되지 않는다.
- 일반 글자(`text`)도 함께 저장해 답글 인용, 알림, 호출 인식에 쓴다.
- 메시지 길이 한도는 2만 자.

## 7. 서버를 항상 켤 수 없는 문제

- 클라이언트는 서버가 꺼지면 "서버 연결 끊김"을 표시하고 자동으로 재접속을 시도한다.
- 서버를 다시 켜면 방·구성원·대화가 그대로 복구된다.
- `data` 폴더를 복사하면 다른 PC에서 같은 서버를 이어서 운영할 수 있다(돌아가며 서버 맡기).
- 파일을 저장하지 않으므로 서버가 매우 가볍다. 나중에 무료 클라우드 서버나 미니 PC로 옮기기 쉽다.

### 외부에서 접속하기

같은 공유기 안에서는 `ws://서버PC주소:7070`으로 바로 접속된다. 집 밖에서 접속하려면 다음 중 하나가 필요하다.

- 공유기 포트 포워딩(7070) — 설정이 필요하고, 암호화(wss)를 따로 붙여야 안전하다.
- Tailscale 같은 사설망 프로그램 — 참여자 모두 설치해야 하지만 설정이 가장 쉽고 안전하다. **권장.**
- Cloudflare Tunnel — 주소 하나로 공개, 암호화 자동.

## 8. 보안

- 비밀번호는 scrypt 해시로만 저장.
- 서버 접속 암호(`SERVER_PASSWORD`)를 설정하면 암호를 아는 사람만 가입 가능.
- 방 구성원만 그 방의 메시지·파일을 받을 수 있다(서버에서 검사).
- 0.1은 통신 암호화가 없다(ws). 인터넷에 직접 공개할 때는 7장의 터널/사설망을 사용한다.

## 9. 깃 브랜치 운영

| 브랜치 | 용도 |
|--------|------|
| `release` | 배포 버전. 테스트 합격한 것만 올라온다. 태그(`v0.1.0`)로 버전 표시 |
| `develop` | 개발 통합. 기능 브랜치가 합쳐지는 곳 |
| `feature/기능이름` | 기능 하나당 하나. `develop`에서 만들고 `develop`으로 합친다 |

흐름: `feature/*` → (테스트) → `develop` → (통합 테스트 합격) → `release` + 태그

합격 기준: `server`에서 `npm test` 전부 통과 + 클라이언트 수동 점검표 통과.
